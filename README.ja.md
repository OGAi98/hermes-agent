## まず、Hermesとは何か

Hermes Agentは、好きな生成AIモデルに「PCや外部サービスで作業する手段」を持たせ、会話だけでなく実際の作業まで任せられるオープンソースのAIエージェントです。

ChatGPTやClaudeのようなAIモデルそのものではありません。Hermesは、AIモデル、ファイル操作、Web検索、ブラウザ操作、定時実行、長期記憶、TelegramやTeamsなどの窓口をまとめて動かすための土台です。

```text
あなた
  ├─ PCのターミナルで依頼
  ├─ ブラウザやデスクトップ画面で依頼
  └─ Teams / Slack / Telegram / Discordなどから依頼
             ↓
       Hermes Agent
  ├─ 選んだAIモデルに考えさせる
  ├─ Web、ブラウザ、ファイル、コマンドを操作する
  ├─ 過去の会話や設定を参照する
  └─ 指定時刻に自動実行して結果を届ける
```

大まかに言えば、次の3つを一つにしたものです。

1. **PCで働けるAIアシスタント**：ファイルを読み書きし、コマンドを実行し、ブラウザを操作できます。
2. **好きな場所から呼べるAIボット**：Teams、Slack、Telegram、Discordなどを会話の入口にできます。
3. **決まった仕事を続ける自動化基盤**：毎朝のニュース収集、定期点検、レポート作成などを自動実行できます。

## 何ができるのか

### 1. 調査して、結果を整理する

Web検索、Webページの本文取得、ブラウザ操作を組み合わせられます。

例えば、次のような依頼ができます。

- 「直近24時間のAIニュースを10件集め、一次情報へのリンク付きで要約して」
- 「競合3社の料金ページを確認し、違いを表にまとめて」
- 「この論文と関連資料を調べ、技術者でない人にも分かるように説明して」
- 「ログイン後の管理画面を開き、表示内容を確認して」

検索だけで終わらず、取得した情報をファイルに保存したり、定時実行したり、チャットへ届けたりできる点が特徴です。Web検索やクラウドブラウザには、Nous Portalの契約または対応サービスのAPIキーが必要です。

### 2. PC上のファイルやプログラムを扱う

Hermesは、許可された作業環境で次のような操作ができます。

- ファイルやフォルダの検索、読み取り、作成、修正
- Gitの差分確認、ブランチ操作、テスト、コミットなどの開発作業
- Pythonやシェルコマンドの実行
- 長時間動く処理の開始、進行確認、停止
- PDFや文書からの文字抽出
- プロジェクト内の指示ファイルを読んだうえでの作業

そのため、コードを書く用途だけでなく、「大量のファイルを分類する」「CSVを整形する」「定期レポートを生成する」といった事務作業にも使えます。

ターミナルの実行場所は、手元のPCだけではありません。公式版は `local`、Docker、SSH接続先、Singularity、Modal、Daytona、Vercel Sandboxを選べます。大切なPCへ直接触れさせたくない場合は、Dockerや別のサーバーを作業場所にできます。

### 3. Webブラウザを操作する

ブラウザ機能を有効にすると、ページを開く、要素を確認する、クリックする、フォームへ入力する、画面を読み取る、といった操作ができます。

利用できる方式には、ローカルのChrome系ブラウザ、Browser Use、Browserbaseなどがあります。単純なWeb検索と違い、JavaScriptで動く画面やログイン後の画面も対象にできます。

ただし、購入、送信、公開、削除など取り消しにくい操作は、指示内容と権限設定を慎重に設計する必要があります。CAPTCHAや多要素認証、サイト側の自動操作対策によって止まる場合もあります。

### 4. TeamsやSlackなどから話しかける

`hermes gateway` という常駐処理を動かすと、普段使うチャットをHermesの窓口にできます。公式ドキュメントには、次の接続先が掲載されています。

- Microsoft Teams、Slack、Google Chat
- Telegram、Discord
- WhatsApp、WhatsApp Cloud API、Signal、SMS
- Email
- LINE、WeCom、Weixin、DingTalk、Feishu/Lark、QQ、Yuanbao
- Mattermost、Matrix、IRC、SimpleX、Buzz
- iMessage（BlueBubblesまたはPhoton経由）
- Home Assistant、ntfy、Webhooks

接続先によって、画像、ファイル、音声、スレッド、リアクション、回答の逐次表示への対応状況は異なります。例えばTeamsは、公式の比較表では画像、スレッド、入力中表示に対応し、音声と一般ファイルの送受信には未対応です。

初期設定は次のコマンドから行います。

```bash
hermes gateway setup
hermes gateway install
hermes gateway status
```

チャットからHermesを使う場合でも、実際の処理はHermesを動かしているPCやサーバーで行われます。外出先からTeamsで指示したい場合は、そのPCまたはサーバーとGatewayが動き続けている必要があります。

### 5. 決まった時間に仕事をさせる

Hermesには定時実行機能があります。自然な言葉、間隔、一般的なcron形式、日時指定で予定を登録できます。

```bash
hermes cron create "every 2h" "Check server status"
hermes cron create "0 9 * * *" "今日の業界ニュースを調べて要約する" --name "朝のニュース"
```

会話中に「毎朝9時にAIニュースを調べてTelegramへ送って」と頼み、Hermes自身に登録させることもできます。

定時実行では、次のことができます。

- 1回だけ、または繰り返し実行する
- 一時停止、再開、内容変更、手動実行、削除
- 特定の作業手順（Skill）を読み込ませる
- 特定のプロジェクトフォルダで作業させる
- 実行結果を元のチャット、指定チャット、ローカルファイルへ届ける
- AIを使わず、決めたスクリプトだけを実行する
- 実行履歴や失敗理由を確認する

定時実行を担当するのもGatewayです。PCを閉じた状態で動かしたい場合は、常時起動するPC、VPS、または対応するクラウド実行環境が必要です。

### 6. 好みや過去の作業を覚えさせる

Hermesには、会話をまたいで残る記憶があります。標準では主に次のファイルを使います。

- `MEMORY.md`：プロジェクトや環境について学んだこと
- `USER.md`：利用者の好み、役割、コミュニケーション方法
- `SOUL.md`：アシスタントの性格や基本姿勢

また、過去のセッションを検索して、以前の作業を思い出させることもできます。外部の記憶サービスを追加する仕組みもあります。

これは「すべてを無制限に覚える」という意味ではありません。長く使える内容を選んで記録し、会話が長くなった場合は内容を圧縮して扱います。機密情報や古くなりやすい情報を何でも記憶させる運用は避け、保存内容を定期的に確認するのが安全です。

### 7. プロジェクトごとのルールを守らせる

Hermesは、作業するフォルダにある次のような指示ファイルを自動的に探します。

- `.hermes.md`
- `AGENTS.md`
- `CLAUDE.md`
- `SOUL.md`
- `.cursorrules`

例えば `AGENTS.md` に「本番反映前に必ずテストする」「日本語で報告する」「このフォルダは変更しない」と書けば、そのプロジェクトでの行動規則として読み込ませられます。

メッセージ内で `@` を使い、ファイル、フォルダ、Gitの差分、URLをその場の参考資料として渡すこともできます。

### 8. よく使う手順をSkillとして再利用する

Skillは、特定の仕事の進め方をまとめた説明書です。必要なときだけ読み込まれるため、毎回長い指示を入力する必要がありません。

例えば、次のようなSkillを用意できます。

- 自社の記事作成ルール
- GitHubのプルリクエスト確認手順
- PDFから表を抜き出す手順
- サーバー点検と報告の書式
- 毎朝のニュース選定基準

Skillは `SKILL.md` を中心としたフォルダで作り、スクリプトや参考資料も同梱できます。Skill Hubから探して導入したり、自分のSkillを公開したりできます。`agentskills.io` の仕様と互換性があります。

### 9. 複数のAI担当へ仕事を分ける

大きな仕事は、子エージェントへ分担できます。例えば「3社を1社ずつ並行調査し、最後に比較表へまとめる」といった使い方です。

子エージェントは別々の会話領域とターミナル作業領域を持ち、親エージェントが結果をまとめます。並列に動かすほど、短時間で終わる可能性がある一方、モデル利用料と外部サービスの利用量は増えます。

### 10. 画像・音声を扱う

対応するモデルとサービスを設定すると、次の機能を使えます。

- 画像を貼り付けて内容を分析する
- 文章から画像を生成する
- 音声メッセージを文字にする
- 回答を読み上げる
- CLIでマイクを使って会話する
- Discordの音声チャンネルで会話する
- ウェイクワードで音声会話を始める

画像生成、文字起こし、読み上げには、選んだ提供元のAPIキーや契約が別途必要になる場合があります。

### 11. エディターや別の画面から使う

HermesはACPという接続方式に対応しており、VS Code、Zed、JetBrains系の対応クライアントから利用できます。チャットだけでなく、ツールの実行状況、ファイル差分、コマンド、承認画面をエディター内に表示できます。

また、OpenAI APIと似たHTTP APIを公開できます。Open WebUI、LobeChat、LibreChatなど、対応する画面からHermesへ接続する用途です。Hermes固有のツール実行や会話の継続もサーバー側で扱えます。

### 12. 大量の依頼をまとめて処理する

JSONL形式で依頼を並べ、数百・数千件を並列実行するバッチ処理があります。主な用途は、AIエージェントの学習データ作成や性能評価です。一般的な日常業務では必須ではありません。

各依頼を別の環境で動かし、会話、ツール呼び出し、成功・失敗、推論の統計を保存できます。途中再開にも対応します。大量のモデル呼び出しが発生するため、料金上限と同時実行数の設定が重要です。

### 13. 自分向けに拡張する

Hermesは次の方法で拡張できます。

- **Skill**：文章で手順や判断基準を教える
- **MCP**：GitHub、データベース、社内APIなど外部ツールを接続する
- **Plugin**：新しいツール、処理前後のフック、記憶方式などを追加する
- **Context file**：プロジェクト固有のルールを設定する
- **SOUL.md / Personality**：話し方や基本姿勢を変える

まずはSkillやMCPで足りるかを考え、独自の認証処理や厳密なプログラム処理が必要になったときにPluginを検討するのが分かりやすい進め方です。

## どのAIモデルを使うのか

Hermesはモデルを内蔵していません。設定した外部またはローカルのモデルを呼び出します。

代表的な選択肢は次のとおりです。

- Nous Portal：モデルとWeb検索、画像生成、音声、クラウドブラウザをまとめて設定
- OpenRouter：多くのモデルを一つの窓口から選択
- OpenAI、Anthropic、Google Gemini、xAIなどのAPI
- ChatGPT/Codex、GitHub Copilot、対応する各社サービスのログイン方式
- Ollama、LM Studio、llama-serverなどのローカルモデル
- OpenAI互換APIを持つ独自サーバー

設定は `hermes model`、会話中の切り替えは `/model` を使います。

```bash
hermes model
hermes
```

「Hermesが無料か」と「AIの利用が無料か」は分けて考える必要があります。Hermes AgentのコードはMITライセンスですが、選んだモデル、検索、ブラウザ、画像生成、音声などのサービス料金は別です。ローカルモデルを使えばモデルAPI料金を抑えられますが、十分なPC性能と設定が必要です。

## Windowsで最初に試す手順

現行版はWindows 10/11で直接動きます。WSL2は必須ではありません。

### 1. インストール

PowerShellまたはWindows Terminalで実行します。管理者権限は不要です。

```powershell
iex (irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1)
```

インストール後は、新しいPowerShellを開いてください。標準の保存先は `%LOCALAPPDATA%\hermes` です。

### 2. 動作確認と初期設定

```powershell
hermes doctor
hermes setup
```

Nous Portalを使う場合は、モデル、Web検索、画像生成、読み上げ、クラウドブラウザをまとめて設定できます。

```powershell
hermes setup --portal
```

### 3. まずは会話だけ試す

```powershell
hermes
```

最初は次のような、安全で結果を確認しやすい依頼がおすすめです。

```text
このフォルダのファイル構成を読み取り、何のプロジェクトか説明してください。
ファイルは変更しないでください。
```

### 4. 使う道具を確認する

```powershell
hermes tools
```

Web検索、ファイル操作、ブラウザ、記憶、定時実行などを、利用場所ごとに有効・無効にできます。CLIでは許可するが、公開チャットのボットでは許可しない、といった分け方ができます。

### 5. 必要になったらチャット接続と定時実行を追加する

```powershell
hermes gateway setup
hermes gateway install
hermes gateway status
```

Windowsでは、Gatewayは通常、ログイン時に起動するタスクとして登録されます。Windowsからログアウトした場合やPCの電源を切った場合は動きません。24時間動かしたいなら、常時起動PCやサーバーでの運用を検討してください。

## Windows版で知っておきたいこと

- CLI、Gateway、ブラウザ操作、定時実行などはWindows上で動作します。
- Hermesのコマンド実行にはGit Bashが使われます。Gitがなければ、インストーラーが専用のPortableGitを用意します。
- ブラウザ機能で必要なNode.jsやChromiumは、インストーラーまたは初回利用時に用意されます。
- Webダッシュボード内の組み込みターミナル画面だけは、ネイティブWindowsでは未対応です。他のダッシュボード機能は動作します。この画面が必要ならWSL2を使います。
- 日本語表示で問題が起きにくいよう、標準入出力はUTF-8に調整されます。
- 設定、認証情報、Skill、履歴、ログは `%LOCALAPPDATA%\hermes` に残ります。再インストール時にフォルダ全体を消すと、これらも失われるため注意してください。

詳しくは[公式のWindowsガイド](website/docs/user-guide/windows-native.md)を参照してください。

## 安全面はどうなっているか

HermesはPCや外部サービスを操作できるため、通常のチャットAIより権限管理が重要です。公式版には次の仕組みがあります。

- 危険なコマンドを検出し、実行前に承認を求める
- 取り返しのつかない一部のコマンドを常に拒否する
- 独自の禁止パターン、許可パターンを設定する
- ファイル書き込み範囲を制限する
- Dockerなど隔離された環境でコマンドを実行する
- チャットを利用できる人を許可リストやペアリングで制限する
- プロジェクト内の指示ファイルに、不審な命令がないか確認する
- 会話、定時実行、利用者ごとの保存領域を分ける
- ファイル変更前のチェックポイントから戻す

標準の `smart` モードでは、危険性を判定し、安全と判断できない操作を承認画面へ回します。`--yolo` や承認機能の無効化は、確認を大幅に減らす代わりにリスクが上がります。

実運用では、次の順で始めると安全です。

1. 専用フォルダだけで試す
2. 読み取り中心の依頼から始める
3. チャットボットの利用者を自分だけに制限する
4. 外部公開するGatewayには、必要最小限のツールだけを許可する
5. 重要な処理はDockerや専用サーバーへ隔離する
6. APIキーをGitや会話本文へ書かない
7. 自動送信・自動公開・削除を含む定時処理は、手動実行で確認してから有効にする

## Hermesが自動で解決してくれないこと

Hermesを入れただけで、すべての機能が無料で使えるわけではありません。

- **判断の正しさ**：AIモデルは誤るため、重要な内容には出典確認や人のレビューが必要です。
- **サービスの契約**：モデル、Web検索、画像、音声、ブラウザに別契約やAPIキーが必要な場合があります。
- **接続先の準備**：TeamsやSlackでは、それぞれの管理画面でBotやアプリの登録、権限設定が必要です。会社の管理者承認が必要な場合もあります。
- **常時稼働**：定時実行やチャット受付には、Gatewayを動かすPCやサーバーが必要です。
- **サイト側の制限**：CAPTCHA、利用規約、自動操作対策、権限不足によってブラウザ操作が止まることがあります。
- **完全な一回限りの実行保証**：通信切断や再起動が絡む外部操作では、重複や実行結果不明の状態を完全にはなくせません。
- **秘密情報の自動保護**：隔離やフィルタリングはありますが、与えた権限と情報の範囲で操作できることを前提に設計する必要があります。

## よくある実用例

### 毎朝のニュースダイジェスト

```text
毎朝8時に、直近24時間のAIとデータ活用のニュースを調べる。
公式発表と報道を区別し、重要な10件を日本語で要約する。
各項目に一次情報のURLを付け、Teamsの指定チャットへ届ける。
```

必要なものは、Web検索、定時実行、Gateway、Teams接続です。最初に手動で同じ依頼を実行し、検索品質とTeamsへの到着を確認してから定時登録します。

### 開発プロジェクトの定期点検

```text
平日の18時に指定リポジトリを確認する。
未完了の作業、失敗中のテスト、依存パッケージの警告を整理し、
修正は行わずSlackへ報告する。
```

プロジェクトフォルダを `workdir` に指定し、`AGENTS.md` に確認範囲と禁止事項を書いておくと、毎回同じ条件で実行できます。

### 社内資料づくりの補助

```text
指定フォルダの議事録と調査資料を読み、
意思決定、未決事項、担当者、期限を表にまとめる。
不明な項目は推測せず「要確認」と書く。
```

ローカルファイルだけで完結させれば、ブラウザやメッセージ連携は不要です。機密性が高い場合は、利用するモデルのデータ取り扱い条件と送信範囲を先に確認します。

### Webページの確認と記録

```text
毎週月曜に3社の料金ページを確認する。
前回保存した内容との差を調べ、変更があった場合だけ報告する。
ページのURL、確認日時、変更箇所を記録する。
```

Skillに比較方法と保存形式をまとめ、Cronで実行すると、繰り返しやすい作業になります。

## 最初に何を試せばよいか

目的別に、必要な機能だけを順番に追加してください。

| やりたいこと | 最初に使う機能 |
|---|---|
| PC上の資料整理やコード作業 | CLI + ファイル + ターミナル |
| 最新情報の調査 | Web検索。必要ならブラウザ |
| 外出先から依頼 | Gateway + 普段使うチャット |
| 毎日・毎週の自動処理 | Gateway + Cron |
| 自社の作業手順を守らせる | `AGENTS.md` + Skill |
| 過去の好みや経緯を引き継ぐ | Memory + Session Search |
| 安全にコマンドを実行 | DockerまたはSSH先 + 承認設定 |
| エディター内で開発 | ACP連携 |
| 社内ツールやDBにつなぐ | MCP。必要ならPlugin |

最初からすべてを設定する必要はありません。まずCLIで一つの会話を動かし、次に必要な道具を一つずつ増やすのが、問題の切り分けもしやすい進め方です。

## このガイドの読み方

Hermesの機能名をすべて覚える必要はありません。最初は次の理解で十分です。

> Hermesは、選んだAIモデルに、あなたの許可した範囲でPCや外部サービスを使わせる仕組みです。会話の入口、使わせる道具、作業ルール、実行時刻、結果の届け先を自分で組み合わせられます。

実際に導入するときは、まず「誰が依頼できるか」「何を操作してよいか」「どこで動かすか」「どのサービスに料金がかかるか」の4点を決めてください。それが決まれば、必要な設定はかなり絞れます。
